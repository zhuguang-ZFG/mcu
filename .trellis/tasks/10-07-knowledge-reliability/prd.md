# 看门狗与串口协议工程

## 目标与依赖

依赖 knowledge-fact-corrections 的 DMA/时间/同步修复，以及 knowledge-prerequisites 的中断、C 布局、状态机、FreeRTOS/IDF 基础。父任务 knowledge-closure。为两板综合项目提供经过边界验证的公共机制。

## 需求

- W1：提供同一帧协议的纯 C 解码/编码/校验与主机工具，不依赖 malloc，不把 UART IDLE 当协议边界。
- W2：F407 与 S3 都提供实际串口协议工程，通信与调试日志分口，兼容旧 UART 入门示例。
- W3：F407 提供 IWDG 主例与 WWDG 窗口对照；S3 提供 TWDT 健康监测及 IWDT 适用边界。版本、时钟容差、是否可停止、调试冻结条件明确。
- W4：只有关键任务持续前进才喂狗；传感器错误但任务仍正常运行不能被误判成任务卡死。
- W5：保存/上报能可靠取得的复位原因，提供可控故障注入；不能在 ISR 无条件喂狗掩盖系统故障。
- W6：新增看门狗/协议教学页与实验说明，连接到 C5、S7/S8、F8 和 P5，完善超时、缓冲容量与最坏处理期限的解释。

## 验收

- W-A1：协议 CRC/COBS 有固定测试向量和独立主机交叉验证；两平台发出的消息可由同一客户端解析。
- W-A2：任意分块、合并帧、噪声、坏编码/CRC、长度 0/64/超长、超时、序号回绕均可验证；越界测试在可用宿主 sanitizer 下通过。
- W-A3：接收队列满、消费延迟和 UART 错误有明确计数与恢复，不无限阻塞、不把丢字节当完整帧。
- W-A4：健康任务全部活跃时喂狗、任一必需任务超时后停止喂狗；时钟回绕、启动宽限、任务恢复与传感器失联模型通过。
- W-A5：两板看门狗和协议工程实际构建；上板可用时验证卡死→复位→原因日志，未实测不能填写复位耗时。
- W-A6：主机 CLI 提供查询/发命令/日志保存/异常帧回归，README 可从干净环境运行，代码与教材同源。

## 边界

本批做独立机制工程，完整记录器由下一阶段集成；不加入任意代码执行、未经确认的 Flash 地址写入命令，不自动烧录当前连接的未知设备。
