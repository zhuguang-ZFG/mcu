# 可靠性工程执行计划

## 硬依赖

knowledge-fact-corrections、knowledge-prerequisites 均验收后开始。前者提供可靠传输游标与时间语义，后者提供可解释的中断/RTOS 运行环境。

## 顺序

1. [ ] 将 design.md 的帧布局、错误码、健康状态接口转为头文件与独立测试向量，先审查端序/长度/CRC 范围。
2. [ ] 实现纯 C codec 和 health 逻辑，宿主随机分块/坏数据/时间回绕/注入延迟测试。
3. [ ] 完成 STM32 与 IDF UART 适配，分别验证字节流与公共逻辑的接口，不复用存在缺陷的旧 ISR 回显。
4. [ ] 完成 IWDG/WWDG 与 TWDT 示例，保存配置来源、计算与可用的复位日志。
5. [ ] CLI 编解码交叉验证、日志、异常帧回归；补读者安装与接线命令。
6. [ ] 写看门狗/复位与协议教材及边界实验，登记工程、导航、先修、实验状态。
7. [ ] 全部质量检查和新平台工程矩阵，通过后提交推送并确认远端 HEAD。

## 测试矩阵

- payload 0/1/64/65，连续分隔符，截断编码、错误 CRC、版本不符、长度不符。
- 每个分割位置逐一 feed；多帧一次 feed；噪声后下一合法帧恢复；模糊输入不越界/无限循环。
- 100ms 超时边界，uint32_t 时间回绕，序号 65535→0。
- 全任务活跃、某任务停止、启动宽限、sensor error 但任务进展、主管自身卡死（硬件兜底）。
- Linux 可用时 sanitizer；Windows 普通构建；ARM 与六类新增/既有 IDF 工程纳入实际清单，不能仅列名字。
