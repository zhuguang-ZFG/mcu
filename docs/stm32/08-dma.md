# S8 DMA：CPU 卸载与总线仲裁

> 🎯 串口收 1KB 数据，中断方式要打断 CPU 一千次；DMA 方式：CPU 说一句"把串口数据搬到这个数组，搬完叫我"，然后该干嘛干嘛——搬完一次中断。这就是 DMA 存在的全部理由。

## 本章精髓

1. DMA 是"第二总线主人"：它和 CPU 共享总线矩阵（回 [S1](01-arch.md)），谁用谁让路——所以 DMA 传输时 CPU 变慢不是错觉，是仲裁。
2. 三个地址方向 + 两种增长：外设地址（固定）、内存地址（自增）、长度（NDTR 倒数）——外设↔内存、内存↔内存三种组合，方向寄存器一位切换。
3. 双缓冲/循环模式是流式数据的灵魂：循环模式收音频/ADC 不间断；双缓冲（乒乓）一块被 DMA 写、一块被 CPU 读，永不打架（见本章动画）。

## 学习目标

- 说清 DMA 请求-应答链路：外设事件→DMA 请求→仲裁→搬运→NDTR 减→（半/全）中断。
- 配通 UART1 的 DMA 接收（循环模式），主循环任意时刻去读都有新数据。
- 解释"流（Stream）/通道（Channel）"二级选择的含义并查表选对（RM0090 §10.3.3 请求映射表）。

## 实物实验

- UART DMA 循环接收 + 主循环打印 NDTR 变化曲线；
- 对比实验：同一 1KB 数据，中断版 vs DMA 版的 CPU 占用（用 [S5](05-systick.md) 时基粗测）。

## 常见坑

- **流/通道选错**：请求映射表查错一格，数据永远不来——以 RM0090 表为准，别背。
- **缓冲区放 CCM**：DMA 写不进 CCM，数据静悄悄丢失（B3/CCM 伏笔）。
- **NDTR 与数据宽度不匹配**：宽度 16 位时 NDTR 是"个数"不是"字节数"——差两倍的经典错。
- **忘清 DMA 中断标志**：TCIF/HTIF 不清，中断无限进（与 EXTI 同款纪律）。
