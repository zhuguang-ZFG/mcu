# S5 SysTick：内核自带的"心跳发生器"

> 🎯 软件延时 `delay(2000000)` 是"数羊"——羊数完没数完全凭感觉，换个频率全乱。SysTick 是 Cortex-M 内核里的一颗"标准秒表"：24 位倒数计数器，归零自动重载并申请中断——精确延时和 RTOS tick 都靠它。

## 本章精髓

1. 三个寄存器全部家当：**LOAD**（重载值）、**VAL**（当前值）、**CTRL**（使能/中断/时钟源）——内核外设，地址固定在 0xE000E010，所有 Cortex-M 芯片通用（这就是 RTOS 移植挑它的原因）。
2. 1ms tick 的算法：`LOAD = 时钟频率/1000 - 1`；168MHz 下 = 167999——减一的梗：从 N 数到 0 是 N+1 个节拍。
3. 计数方向与标志：COUNTFLAG 读过自清——"读它"这个动作本身有副作用，调试时要看透。

## 学习目标

- 写出毫秒级 `delay_ms()` 与微秒级 `delay_us()`（查询 COUNTFLAG 方式）。
- 配置 SysTick 1kHz 中断并实现毫秒级系统时基 `g_tick`。
- 解释为什么 RTOS 都选 SysTick 当 tick（可移植性）以及它的中断优先级为什么设最低（F3 联动）。

## 实物实验

- 逻辑分析仪测 PF6 翻转周期：SysTick 延时版 500ms±0.1%，软件延时版误差肉眼可见——同一块板，两种"时间观"的实测对比。

## 常见坑

- **忘减一**：`LOAD=168000` 得到的是 1.000006ms——长期计时漂移的隐蔽来源。
- **中断里又调 delay_ms**：查询式延时在 ISR 里死等，把 tick 中断自己堵死（嵌套规则回 S4）。
- **g_tick 忘加 volatile**：主循环永远看不到它变（C3 的经典现场）。
- **24 位上限忘检查**：LOAD 最大 0xFFFFFF；低速时钟源（/8）就是为长周期准备的。
