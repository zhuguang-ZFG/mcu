# C0 为什么嵌入式 C 是另一种 C

> 🎯 在电脑上，数组越界=段错误弹窗；在单片机上，数组越界=隔壁外设的寄存器被改写，电机突然转了一下——没有弹窗，只有事故。

## 本章精髓

1. 裸机没有"运行时爸爸"：没有 MMU、没有段错误、没有 GC，越界/野指针的后果直接落在硬件上。
2. C 在嵌入式里是"高级汇编"：每一行都能对应到确定的机器行为——这正是我们选它写驱动的原因。
3. 资源观不同：RAM 按 KB 计、Flash 按 MB 计，`malloc` 不是想用就能用。

## 学习目标

- 能说出裸机 C 与应用层 C 的四条本质差异（无 OS、内存极小、直接碰硬件、启动从复位向量开始）。
- 能用"地址+宽度"的语言描述一次寄存器写操作。
- 接受并记住本站的纪律：先懂硬件，再写代码。

## 先修

- 会写基础 C（函数、指针、结构体的语法层面）。

## 先跑起来（10 分钟 quick win）

跳到 [S0](../stm32/00-env.md) 把灯点了再回来——亲眼看到 `*(volatile uint32_t*)0x40021418 = ...` 让红灯亮灭，本章的每句话都会变得具体。

## 小节结构

| 小节 | 内容 | 四件套 |
|---|---|---|
| 没有 OS 的世界 | 复位向量→main 的启动事实；崩溃时没有蓝屏只有 HardFault | 代码分析 |
| 内存按 KB 计 | F407 的 192KB SRAM 怎么分（栈/堆/全局）；为什么嵌入式慎用 malloc | 配置 |
| C 与硬件的直线 | 寄存器就是"有名字的地址"；volatile 预告（C3 详讲） | 代码分析 |
| 工具链即世界观 | 交叉编译四件套简介，指向 [B0](../build/00-toolchain.md) | 库解析 |

## 记忆锚点

::: tip 一句话记住
**应用 C 出错弹窗，裸机 C 出错冒烟。** 写每一行前问一句：这行代码落在硬件的哪个地址上？
:::

## 实物实验

- 用 [E01](../lab/e01-blink.md) 的 GDB 环节：故意把 BSRR 地址写错一位（`0x40021419`），烧录观察——灯不亮，芯片也不报错。体会"硬件不弹窗"。

## 常见坑

- **把 PC 习惯带过来**：`printf` 调试、无限内存假设、阻塞死等——裸机里每个都要重新挣得。
- **以为全局变量"天生在 RAM"**：它的初值其实存在 Flash，启动代码搬过来的（[C1](01-memory-model.md) 的料）。
- **忽略初始化顺序**：main 之前还有 Reset_Handler 的一整套准备（[B4](../build/04-startup.md)）。
