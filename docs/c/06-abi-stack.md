# C6 调用约定与栈帧：一次函数调用的全程直播

> 🎯 你打电话请外援修水管：报地址（参数）、记下自家门牌（返回地址）、外援自带工具箱（保护现场）、修完按门牌回来（返回）。CPU 调用一个函数，干的就是这四件事——而且全是用栈完成的。

## 本章精髓

1. 函数凭什么"调用完就回来"？——LR 寄存器与压栈返回的双重机制。
2. 局部变量凭什么"用完自动回收"？——栈帧随 sp 指针移动而生灭，零成本。
3. 为什么中断能打断任意函数还能还回去？——因为现场全在栈上，而栈是每个执行流自己的。

## 学习目标

- 能画出一次函数调用前后的栈布局变化（sp、保存的 lr、局部变量）。
- 能背出 AAPCS 的分工：r0–r3 传参、r0 返回值、r4–r11 谁用谁保存、sp/lr/pc 各管什么。
- 能在 `objdump` 反汇编里一眼认出函数的 prologue（push/sub）与 epilogue（pop）。
- 能用 GDB 单步观察 sp/lr/pc 的真实变化（衔接 [实物实验](#实物实验)）。

## 记忆锚点

::: tip 一句话记住
**参数 r0 到 r3，多余的上栈找；返回值 r0 里抱；r4–r11 谁用谁保管；lr 记着回家道。**
:::

## 实物实验

- **装备**：霸天虎板 + ST-Link + 第 0 章工程 + OpenOCD/GDB。
- **观测点**：`bl add_two` 执行前后各读一次 `sp`、`lr`、`pc`；进入函数后再读一次栈顶两字（`x/2xw $sp`）——第二个字就是返回地址。
- **预期现象**：`push {r4, lr}` 后 sp 减 8；`pop {r4, pc}` 后 sp 复原，pc 精确落回 `bl` 的下一条指令。
- 交叉引用：[实验中心 E02 待建](../lab/index.md)。

## 常见坑

- **中断里也在用同一个栈**：ISR 的硬件压栈发生在任务栈上，栈预算要算上最坏中断嵌套——RTOS 章节会回头算这笔账。
- **递归无界 = 栈溢出踩堆/全局区**：裸机没有 MMU 兜底，症状是"变量莫名其妙变了"，HardFault 都不一定报。
- **误以为 `lr` 不用保存**：函数里再调函数（非叶子函数），第一次调用就把 lr 覆盖了——所以非叶子函数的 prologue 一定有 `push {..., lr}`。
- **`main` 里 `return` 会怎样**：启动代码把 `__main` 的返回地址设为死循环，return 不会"回到命令行"。
