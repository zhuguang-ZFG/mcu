# C5 函数指针与状态机：中断驱动代码的基本功

> 🎯 中断来了，硬件只负责跳到一个固定地址——"接下来干什么"全靠向量表里那个**函数指针**。而你要写的所有"中断驱动"代码，归根结底都是这三件套的排列组合：函数指针 + 状态机 + 环形缓冲。

## 本章精髓

1. 函数指针=可变的跳转目标：向量表、回调注册、命令分发表，本质都是"存起来的地址"。
2. 状态机是中断代码的"记账本"：中断里只做记账（改状态+搬数据），不做业务——业务留给主循环。
3. 环形缓冲是生产者-消费者的最小解：中断生产、主循环消费，无锁安全的条件只有一个读指针一个写指针。

## 学习目标

- 能手写：回调注册表（如按键事件注册）、查表法状态机、单生产单消费环形缓冲。
- 能说出"中断里为什么不能恋战"，并用执行时间账说明。
- 理解 `typedef void (*cb_t)(void);` 这种声明的读法（右左法则）。

## 先跑起来（10 分钟 quick win）

读 00-blink 启动文件里向量表任意一行：`.word EXTI0_IRQHandler`——这就是一个"函数指针存在 Flash 里"的实例。在 C 里写同名函数，链接器就把它"填进表里"。

| 小节 | 内容 | 四件套 |

## 记忆锚点

::: tip 一句话记住
**中断三件套：指针记账、状态归档、缓冲转运；中断里只做快递分拣，不下厨房。**
:::

## 实物实验

- 在 00-blink 基础上加 EXTI 按键中断（前瞻 [S4](../stm32/04-nvic-exti.md)）：中断里只翻转一个 `volatile uint8_t evt=1;`，主循环检测到就换灯色——亲手体会"记账 vs 办事"的分工。

## 常见坑

- **函数指针类型不匹配**：签名差一个参数，调用就是 UB——编译器未必报警（老代码里 `void(*)()` 与 `void(*)(void)` 不一样）。
- **环形缓冲读写指针写反**：读指针只能消费者动、写指针只能生产者动，交叉修改即翻车。
- **状态机里做长延时**：中断/主循环统统被拖死——延时本身就该是一个状态（等超时事件）。
- **查表数组忘加 const**：白白吃掉 RAM（回 [C1](01-memory-model.md) 的 const 经济学）。
