# F8 移植 FreeRTOS 到霸天虎：从裸机工程到多任务

> 🎯 前面七章的机制，这一章全部落地：在我们的寄存器工程上，让 FreeRTOS 跑起来。移植的本质是**三个异常函数的改名接管**——SVC 启动第一任务、PendSV 切换、SysTick 报时，其余全是体力活。

## 本章精髓

1. 移植 = 拿对 port 层 + 改三处异常向量：ARM_CM4F 的 port.c/portmacro.h 拿来即用；FreeRTOS 用 `vPortSVCHandler/xPortPendSVHandler/xPortSysTickHandler` 三个名字——与我们启动文件的 SVC/PendSV/SysTick 向量对上即可（改向量表或 #define 映射两法）。
2. 中断优先级两组配置别踩：`configKERNEL_INTERRUPT_PRIORITY`（内核相关：PendSV/SysTick 必须最低）与 `configMAX_SYSCALL_INTERRUPT_PRIORITY`（能调 API 的中断上限）——数值逻辑"数值越大优先级越低"，搞反全系统灵异。
3. heap 与栈的预算结构：heap 供任务栈/TCB/队列，与裸机 main 栈（链接脚本 _Min_Stack_Size）是两套预算——RTO S化的 RAM 总账要重算（F7 方法+B5 审计）。

## 学习目标

- 完成移植七步并跑通双任务闪灯：加源码→加 port→配 FreeRTOSConfig.h→接异常→调优先级→改时钟→跑通。
- 读懂 FreeRTOSConfig.h 每一行的作用（本站给逐行注释模板）。
- 用 GDB 验证：vTaskStartScheduler 后第一个任务如何经 SVC 启动。

## 常见坑

- **启动文件与内核抢 SysTick**：裸机延时用的 SysTick_Handler 与内核冲突——延时改用 vTaskDelay 或 DWT。
- **中断优先级一刀切**：把 0（最高）给了能调 API 的中断——数值逻辑换算错，FromISR 调用即炸。
- **heap 太小静默创建失败**：xTaskCreate 返回 errCOULD_NOT_ALLOCATE_REQUIRED_MEMORY 没人检查——所有创建 API 查返回值。
- **FreeRTOSConfig.h 抄别家**：F103 的 config 搬到 F407，TICK 时钟源/优先级位数全错（F4 是 4 位优先级）。
