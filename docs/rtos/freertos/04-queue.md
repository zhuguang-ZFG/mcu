# F4 队列：环形存储 + 两个阻塞列表

> 🎯 队列是 RTOS 里最忙碌的传送带：数据从这头进那头出，满了送件人排队（写阻塞），空了取件人排队（读阻塞）——FreeRTOS 用一个结构体装下全部：一段环形存储 + 两张"排队名单"。

## 本章精髓

1. Queue_t 三件套：`pcHead/pcWriteTo/pcReadFrom` 管理的环形缓冲区 + `xTasksWaitingToSend` + `xTasksWaitingToReceive` 两张阻塞列表——所有队列行为都是这五样的组合。
2. 发送是"拷贝"不是"传指针"：xQueueSend 把数据**按值拷进**环形区——简单安全，代价是大数据拷贝慢（这就是为什么 F6 的通知更快、大对象传指针）。
3. 阻塞有超时且有公平：阻塞时任务挂进对应列表并按优先级排序——唤醒时优先级最高的先拿到；超时到点自动复活带错误码。

## 学习目标

- 画出队列结构体五要素与一次"满队列发送阻塞→接收唤醒"的完整时序。
- 逐行讲 xQueueGenericSend 的关键分支：有空位/覆盖写（xQueueOverwrite）/阻塞入队。
- 完成 ISR→任务通信实战：串口中断 `xQueueSendFromISR` + 任务接收打印。

## 先跑起来（10 分钟 quick win）

按键中断里 `xQueueSendFromISR` 发按键值，任务里 `xQueueReceive(..., portMAX_DELAY)` 收到就翻灯——第一个"中断→任务"的标准管道。

## 记忆锚点

::: tip 一句话记住
**队列=环形仓库+两张候客名单；发送按值拷贝，ISR 用专用通道，阻塞按优先级叫号。**
:::

## 实物实验

- quick win 全链路 + 把队列长度改成 1，连按快键观察丢失——亲手验证"深度不够就丢/堵"的工程取舍。

## 常见坑

- **中断里用普通版**：xQueueSend 在 ISR 里 = 定时炸弹；认准 FromISR 后缀并处理 pxHigherPriorityTaskWoken。
- **大结构体整包拷进队列**：队列项尺寸按字节拷贝计费——大对象传指针（注意生命周期，C1 复训）。
- **阻塞时间写 0 抱怨收不到**：`xQueueReceive(q,&d,portMAX_DELAY)` 与 `0` 的语义天差地别。
- **拿队列当互斥锁用**：保护共享资源请用互斥量（F5），队列干的是"传递"不是"保护"。
