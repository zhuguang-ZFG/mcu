# R7 移植 RT-Thread 到霸天虎：Nano 手动移植 → 标准版

> 🎯 F8 我们手动接管了 FreeRTOS 的三个异常；这一章走两条路：先用 **Nano**（3KB 的迷你内核）手动移植感受"最小成本"，再用**标准版 BSP** 体验"设备框架+finsh"的完整生态——两条路都走通，RT-Thread 的版图在你心里就完整了。

## 本章精髓

1. Nano 手动移植四件套：内核源码（src/ + libcpu/arm/cortex-m4）+ `rtconfig.h`（裁剪配置）+ board.c（实现 `rt_hw_board_init`：时钟/SysTick/堆）+ 三异常接管（与 F8 同款：PendSV/SysTick/HardFault）——内核无关板卡，板卡全在 board.c。
2. SysTick 的双重身份：`rt_hw_board_init` 里配好 1ms tick，ISR 里调 `rt_tick_increase()`——与 FreeRTOS 的 xPortSysTickHandler 异曲同工。
3. 标准版的价值在"带 BSP"：RT-Thread 仓库自带大量 STM32 BSP（同系 F407 BSP 可就近借鉴）——复制最近似 BSP 改引脚/时钟/外设，比从零写快十倍；finsh 与设备框架随 `rtconfig.h` 开关即来。

## 学习目标

- Nano 路线：手动移植并跑通双线程闪灯 + finsh（可选）。
- 标准版路线：以最接近的 F407 BSP 为母本改成霸天虎版（时钟源、LED/串口引脚、FLASH/RAM 参数）。
- 说出 Nano 与标准版在"设备框架/软件包/构建方式"上的三个分野，并按项目需要选路。

## 实物实验

- Nano 版双线程 + finsh 版本二选一跑通；
- 标准版 BSP 改造后 `list_device` 看到 pin/uart 设备注册在册——生态落地的实锤。

## 常见坑

- **rtconfig.h 与源码版本不配**：配置项名随版本漂移——从官方模板改，不抄旧文。
- **board.c 堆边界符号错**：链接脚本符号（如 `end`/`_estack`）与 rt_hw 堆参数对不上，首次 malloc 即崩（B3 复训）。
- **SysTick 冲突**：裸机延时与内核 tick 抢 SysTick——同 F8 教训，统一交给内核。
- **BSP 时钟源不改**：母本 BSP 用 25MHz 晶振而霸天虎不同频——串口波特率全错的经典翻车（回 S2 核对 HSE）。
